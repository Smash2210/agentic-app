## Decisions made in review

1. **Policy numbers in the docs (accepted).** The API descriptions and generated docs state "over 25
   USD", "USD, EUR, GBP, INR" and "75%". These duplicate values that live in `data/policies/`
   (constitution Principle II). Decision: keep them, because API users need the numbers to use the
   API. Risk noted: if a policy number changes, the rules engine follows the policy file
   automatically, but these descriptions must be updated by hand. `openapi.json` is regenerated
   from the code, so the change shows up in the diff once the description is edited.
2. **Script name `scripts/exports_openapi.py` (kept).** Commit `ea9d17d` made its usage text and
   error message match the file name, so it is consistent.

## Problems found in the workflow (not the docs)

- **The skill referenced a file that did not exist.** `SKILL.md` step 3 points to
  `references/style.md`, which had not been created, so the first run worked without the style
  rules. Fixed: `style.md` added with the human review commit. Lesson: a skill's reference files
  are part of the skill and need to be checked like code.
